## 海报 vs 内容卡：两套逻辑，不要混

`10`–`15` 用的是 `block: "poster"`，它和 `cover` 不是同一个东西：

| | `cover` | `poster` |
|---|---|---|
| 职责 | 索引，告诉读者这套有几张、分别讲什么 | 拦截，只让人停下来点 |
| 元素数 | 不限（目录 + 统计 + 提示） | **≤5**：眉题 / 标题 / 色条 / 副标题 / 标签条 |
| 标题字号 | 96–100px | **168–178px**，靠字号本身压住画面 |
| 强调色 | 允许多处 | **只给一处**（`blk` 色块或 `hi` 变色，二选一） |
| 底色 | 纸底即可 | 走极端明度，且要带质感（`posterTexture`） |

判断标准：**这张图的任务是「让人点进来」还是「告诉人里面有什么」**。前者用 poster。

`10`–`15` 六套都同时支持 `poster` 和 `resource`/`items`/`qa`，可以整套出图。
但**海报的底色不能直接当正文页底色用**：深色海报（10 / 15）的 `colors.paper` 必须也是深色，
否则白底配米白字会糊成一片 —— 这是实测踩过的坑。
反之 12 的封面是饱和橙，连发九张正文会刺眼，所以它的 `colors.paper` 单独降成了浅橙 `#FFEFD9`。

竖版的诚实限制：横图那套「标题字高占画面 1/3」是按 1500×600 总结的。1080×1440 的内容列只有
936px 宽，每行最多 4 个中文字，字号封顶约 230px。所以竖版靠**行数 + 对比**堆冲击力，不是无限放大字号。
中文行高必须 ≥1.16 —— 从横图搬来的 1.04 会让三行字糊成一团。

### `seal` 和 `blk` 不能同时用同一个信息

海报只有「一处强调色」的额度。如果标题里已经用 `<span class="blk">5</span> 份资料`
做了色块，再在右上角加一枚 `seal: ["5","份资料"]`，就同时犯了两条：

1. 强调色（朱红/橙/黄）出现两次，视线不知道该先看哪
2. 「5 份资料」这个信息说了两遍

**同一张海报里 `seal` 和 `blk`/`hi` 二选一。** 要印章就去掉标题色块，要色块就去掉印章。
留色块：它在标题内部，是主焦点，权重远高于角落的印章（实测六套出图后统一去掉了 `seal`）。
`seal` 是可选字段，不写就不渲染，不会占位。

## 生插画横带：主体必须居中，且两侧要有等重配景

`13`–`15` 的插画带是 21:9 横幅，裁成 1080×520 后贴在封面顶部。封面在信息流里是**缩略图**，
主体偏一侧会让整张图视觉重心失衡，第一眼抓不到东西 —— 用户在 `14` 上踩过一次：
第一版提示词明写「人物在右侧三分之一，左边大量留白」，出来左侧整幅空云，缩略图几乎只剩一团色。

写提示词时把这三件事**写死**：

1. `STRICTLY CENTRED COMPOSITION` + 「角色头部正好位于画面水平中心」
2. 左右各放一组**等重配景**（左书架 / 右绿植+马克杯），明确写「两侧视觉重量相等、不留大片空白」
3. 桌面或地平线**横跨整个画面宽度**，把左右串起来

不是只说「居中」——模型会把配景一起堆到一边。必须同时指定左右各有什么。

### 插画的配色也要参与风格区分

`13` 和 `14` 都是「卡通角色 + 桌面场景 + 巨标题」，版式天然接近，**区分度只能靠色相**。
第一版 `14` 用了薄荷绿背景，和 `13` 的薄荷奶油底撞在一起，两套并排时分不出谁是谁。

定色时按「明度 + 饱和度」错开，不要只看色相名字：

| | 底色倾向 | 主体色 | 和别的怎么分 |
|---|---|---|---|
| `13` 毛绒潮玩 | 薄荷绿，浅、低饱和 | 墨绿 | 冷调 |
| `14` 动漫工位 | 暖杏 + 奶油米，浅、低饱和 | 墨棕 + 珊瑚橙 | 暖调 |
| `15` 微缩立体书 | 深青，**暗** | 金黄 | 明度压死 |
| `12` 活力橙 | 橙，**高饱和** | 白 | 饱和度拉满 |

所以 `14` 是低饱和暖色，不是高饱和橙 —— 否则又会被 `12` 吃掉。

生图时要**明写禁止项**，`14` 这版提示词里写的是
`ABSOLUTELY NO GREEN anywhere in the image - no mint, no sage, no teal`，
并把配景也从绿植改成「暖陶土马克杯 + 小仙人掌」，否则模型会随手补一片绿回来。

`14` 的成品是 `14-work.jpg`（3168×1344）。
中间还试过一版薄荷绿的 `_rejected-14-mint.jpg`，留档但**不要用**。

## 素材池：换内容不用重新生图

`assets/art-pool/` 存了 13 张 21:9 横带，`pool.json` 是清单（每张标了场景和适合的主题）。
发新内容时挑一张贴到封面顶部即可，**插画不会自动跟着主题变**。

| 风格 | 张数 | 场景 |
|---|---|---|
| `13` 毛绒潮玩 | 3 | 看书 / 敲电脑 / 举放大镜 |
| `14` 动漫工位 | 4 | 办公 / 敲代码 / 写字 / 读书 |
| `15` 微缩立体书 | 4 | 山脉 / 森林 / 城市 / 海岸 |

换插画就是改 spec 的 `art` 字段指向另一张，再跑一次 `render_cards.js`。
`art` 路径写错会**直接失败并删掉那张 PNG**，不会给你一张缺图的封面（细节见 `STYLE-01-editorial.md`）。

池子不够用时再按上面的提示词规则补一张：21:9、主体居中、左右等重配景、明写禁止色、全图无文字。

## 已定的两个：`01` 和 `06`

2026-10-12 用户拍板：**只启用 01 和 06**，其余重新做。

## `02`–`05` 作废，编号不再复用

用户对 02–05 的反馈是：**版式太像 PPT / 报表**。

具体指这些特征，新风格一律避开：

- 三栏/多栏等分网格，标题在上、正文在下的标准对称结构
- 圆角矩形卡片 + 阴影 + 图标配文字，一行一个 item
- 图标/序号居左、说明文字居右的表格式排布
- 看起来像「一页幻灯片」而不是「一张可以截图保存的图」

token 文件留着当记录，但**状态是作废，不要拿去出图**，编号也**不要再用**。
新增风格从 `07` 开始往后排（跳过 02–05）。

## 解析用户的说法

| 用户说 | 怎么处理 |
|---|---|
| 「用 01」「风格 1」「STYLE-01」 | 走 `STYLE-01-editorial.json` |
| 「杂志编辑风」「米白那套」 | 命中 `01` |
| 「插画那套」「有插画的」 | 命中 `06` |
| 「跟上次一样」 | **不要假设等于 01**。新会话可能没有上下文，直接问编号 |
| 「2」「02」 | **已作废**。告诉用户 02–05 是被判掉的版式，编号不复用，问是否要看新候选 |
| 「随便」「都行」 | 默认 `01`，并在交付时说明用了哪套，方便用户纠正 |

编号一旦分配就不再复用、不重排。`01` 永远是 2026-10 定的杂志编辑风，即使后来调整过参数。
`02`–`05` 已作废，编号作废也不复用。新增风格从 `16` 开始。

## 新增一套风格（用户说「以后还会有其他喜欢的风格」时走这里）

1. **先做出来再看编号**。用户通常是"看到成品喜欢上了"才编号的，不是先给编号再设计。
   所以流程是：按用户描述做一套 → 用户认可 → 分配编号 → 归档。

2. **建两个文件**，和 `01` 同目录：
   - `STYLE-NN-<slug>.json` —— token，字段与 `STYLE-01-editorial.json` 完全一致
   - `STYLE-NN-<slug>.md` —— 规格文档，字段说明与 `STYLE-01-editorial.md` 对齐
   （`slug` 用小写英文连字符，例如 `business-navy`、`vivid-gradient`）

3. **回本文件登记**一行，填全五列。

4. **配色替换时的取值范围**：新风格的 block 结构可以照抄 `01`（五个 block 是通用词汇），
   通常只需换 `colors` 和 `type` 两个 token 段。只有当排版结构本身不同（例如圆角卡片、
   左图右文）时才需要改 `render_cards.js`，并在 SKILL.md 的 Procedure 里说明。

## canvas 与风格无关

`STYLE-NN-*.json` 里的 `canvas` 只是这套风格的**默认出图尺寸**，不是它的定义。
换发布平台一律走命令行 `--width / --height`，**永远不要改 token 文件的 canvas** ——
改了就等于把这个编号的风格永久改坏，而编号是不复用的。

登记新风格时一并写 `supportedCanvas`（调校过的尺寸列表）。渲染器读到不在列表里的尺寸
会打 WARNING 提醒看图，这是有意的：宁可让模型看见坏结果，也不要静默糊过去。

## 字体可用性

两套字体都依赖本机安装：
- 思源宋体 `Noto Serif SC` / `Source Han Serif SC`
- 思源黑体 `Noto Sans SC` / `Source Han Sans SC`

Windows 上一般已随系统安装。若渲染出来中文变成衬线回退或方框，先确认字体在不在，
再考虑在 style 的 `fonts` 里改字体栈 —— 不要擅自换成系统默认字体，风格会跑掉。
